# 变声器设计

> 范围：在「麦克风混音助手」的实时麦克风链路上增加可配置的人声变换。
> 本文记录设计规格与当前实现进度，不含实现代码。实现位于 `crates/audio-core/src/voice/`、
> `crates/audio-session`、`crates/app-config`、桌面宿主与界面；调研依据见[变声器调研](变声器调研.md)。
> 产品能力边界是经典 DSP 实时变声，不提供音色克隆、模型下载或推理运行时。

## 1. 目标与范围

### 目标

- 对真实麦克风人声做实时音高与共振峰变换，支持女声、男声、小孩、低沉、机器人、对讲机等预设。
- 用户可在界面调整参数、保存自己的预设，并通过全局热键、手机遥控和命令行切换。
- 提供 3 秒人声试听，让用户确认效果，同时不把试听声音送给对方。
- macOS 与 Windows 同批交付、同一套行为与验收标准。

### 首发范围

- 音高与共振峰移调。
- 噪声门、三段 EQ、软削波、环形调制。
- 内置预设与 GUI 保存的用户预设。
- 全局热键：旁路切换、上一个预设、下一个预设。
- 手机遥控：变声启用/关闭与预设切换。
- CLI：配置读写、播放时指定预设或关闭变声。
- 3 秒人声试听。
- 配置持久化与旧配置兼容。

### 不做

- 神经网络音色克隆、模型下载与推理运行时。
- 混响、和声/齐唱、独立降噪。
- 变声算法运行期更换或块长热调整。
- 托盘新增变声菜单。
- 对音效素材做任何变声处理。

### 平台

两端功能一致。差异只在音频后端、设备引导与构建方式，不在产品行为。

## 2. 关键决策

| 决策 | 结论 |
|---|---|
| 插入位置 | 采集侧，漂移重采样之后、写环形缓冲之前 |
| 处理对象 | 仅真实麦克风人声，单声道处理后复制成立体声 |
| 算法后端 | Signalsmith Stretch（指标先行选定，10 ms 块；人工听感与 Windows 真机待生产验收） |
| 旁路 | 关闭或临时旁路时恢复现有单限幅链，不运行人声算法或路径限幅 |
| 试听 | 3 秒录制后本机回放；关闭或旁路时复用会话人声链只录不转发，正式转发保持原声；启用时从人声路径限幅之后取音 |
| 预设 | 内置处理预设 + 用户预设，存储在共用 TOML；选择预设只加载参数，不自动启用变声 |
| 关闭 | 只由 `enabled` 开关或临时旁路控制，不设「原声预设」 |
| 切换入口 | GUI、全局热键、手机遥控、CLI |
| 与音效关系 | 不进入正式播放、音效试听、监听、自检；不改变单音效门控。变声启用时，人声与音效各自独立限幅后再混合，最后保留末端安全限幅 |
| 双端 | 同一提交、同一发布门禁；Windows 真机验收通过才算完成 |

## 3. 架构

### 数据流

```
真实麦克风 → 下混单声道 → 漂移控制重采样 → 人声链 → 环形缓冲 → 人声增益 → 人声限幅
                                                                              │
                                                                              └─ 人声试听 tap → 3 秒记录区 → 本机输出

音效：控制侧解码 → 准备到输出采样率 → 播放器 → 音效增益 → 音效限幅
                                                              │
人声限幅 ─────────────────────────────────────────────────────┴─→ 混音 → 末端安全限幅 → 电平表 → 输出

监听：独立输出流，仅音效
音效试听：独立工作线程，仅音效
自检：独立流与独立缓冲，不经过人声链
```

变声未启用或临时旁路时，跳过人声限幅与音效限幅，保持现有「混音后单限幅」链，不增加额外延迟。变声启用时，两条路径各自限幅后再混合，末端安全限幅只负责合并后的过载保护。

关闭 / 旁路时的试听复用路径：

```text
关闭 / 旁路时点试听：
麦克风 → 下混 → 漂移重采样 → 会话人声链（仅试听） → 3 秒记录区 → 本机回放（−3 dBFS 试听限幅）
                              │
                              └─ 环形缓冲仍写干声，正式转发不变
```

试听复用会话内已有的人声链，不新建第二套算法实例；它不改变 `enabled`，不把湿声写入环形缓冲，也不影响对方听到的原声。

人声链运行在输出采样率上。目标是在跨 44.1 kHz 与 48 kHz 设备时保持同一预设的音高与共振峰听感一致；进程内离线验证已通过 1 半音门槛，44.1 kHz 真机仍为 D 级。

### 试听链路复用

- 会话在构建时即创建人声链，`enabled=false` 只决定正式转发阶段，不销毁该链。关闭或临时旁路时，试听复用这条会话人声链，因此不需要第二套算法实例，也没有试听实例的创建与销毁生命周期。
- 采集回调在 Off 或临时旁路阶段照常把干声写入环形缓冲，同时把同一份样本喂给会话人声链；湿声只写入预分配的 3 秒记录区。
- 试听代次变化时复位会话人声链并从零预热，跳过算法延迟对应的初始样本，避免录到开头的静音或上一段残留。
- 记录区容量固定，写入只推进原子索引，不加锁；取消、完成或阶段变化时停止写入并复位链。
- 回放时对采集预览应用 −3 dBFS 试听限幅；变声已启用且处于 Wet 时，试听从渲染侧人声路径限幅之后取音，不再重复限幅。
- 试听期间正式转发保持原声（关闭/旁路）或正常湿声（启用），两者互不影响；试听不改变 `enabled`、预设与参数。

### 实时契约

- 人声链的 `process()` 不分配、不加锁、不做文件 IO、不调用平台设备 API。
- 所有工作缓冲、FIFO、效果器状态在会话启动或预设创建时预分配。
- 参数从预分配快照读取；预设切换不重建算法实例。
- 正式转发的人声链实例只在音频会话启动时创建；关闭会话时在所有者线程回收。
- 关闭或旁路时的试听复用会话人声链，不额外创建实例；采集侧在试听代次变化时复位该链并重新预热，预热样本只进入记录区，不进入正式转发。
- 回调内异常由现有 `catch_unwind` 保护，人声链不新增跨 FFI 的 panic 路径。

### 流式适配与延迟

Signalsmith Stretch 的 `process(input, output)` 允许输入与输出帧数不同。人声链的「块长」指算法分析块，不是采集回调的处理粒度：

- 会话启动时确定算法块长，默认 10 ms；技术验证若证明该值不满足音质或延迟门槛，按验证记录调整并固定。
- 采集回调可以小于或大于算法块；输入 FIFO 接收重采样后的单声道样本，输出 FIFO 提供环形缓冲所需帧数。
- FIFO 容量按算法块长、内部采集分块上限与最大输出积压计算，启动时一次性分配；不假设设备回调存在固定上限。
- 人声算法延迟由算法报告值、FIFO 水位与块长组成；目标不超过 30 ms。
- 变声启用时，人声与音效各增加约 2 ms 路径限幅延迟；末端安全限幅保持约 2 ms。关闭变声或临时旁路时跳过路径限幅，恢复现有单限幅链。
- 输入欠载时输出静音并计数，不阻塞回调；输出积压超过容量时丢弃最旧数据并计数，不无限增长。
- 单次回调的最坏处理耗时必须小于最小支持回调周期（按平台实测 128 / 256 / 512 帧），平均占用率不能替代该判据。

### 开关与切换

关闭变声时人声链直通，不增加算法或路径限幅延迟；人声链输出与输入逐样本一致，末端安全限幅仍按现有链路工作。

启用采用 tee，而不是把人声链直接串入转发路径：

1. 非实时线程创建或复用当前会话的人声链实例，装载当前参数并预热。
2. 采集回调继续把干声写入环形缓冲，同时把同一份样本喂给人声链；湿声先只进入输出 FIFO，不写环。
3. 湿声 FIFO 达到可切换水位后，渲染侧在块边界把写环来源从干声切到湿声，并用约 20–30 ms 交叉淡化遮蔽过渡。
4. 干声在预热期一直写环，因此不会抽干环形缓冲，也不触发欠载。

关闭采用相反方向：

1. 渲染侧先淡出湿声并切回干声，再停止向人声链喂样本。
2. 淡出完成后解除人声与音效路径限幅，回到现有单限幅链。
3. 音效路径限幅在解除前先等到增益恢复到 1 或完成淡出，避免瞬间响度上跳。

湿声恒晚于干声一个算法延迟 L。任何干湿切换都必然出现一次时间不连续：

| 过渡 | 必然结果 | 承诺 |
|---|---|---|
| 启用 | 人声重复至多 L ms | 无爆音、无欠载、无长断音；交叉淡化只避免突变，不消除重复本身 |
| 关闭 | 人声跳过至多 L ms | 无爆音、无欠载、无长断音；淡出只避免突变，不消除跳过本身 |
| 湿→湿切预设 | 无时间跳变 | 参数在块边界平滑，无咔哒、无长空隙 |
| 湿→关闭/旁路 | 同关闭 | 同关闭 |

因此设计不再承诺「零空隙」或「完全避免梳状滤波」；承诺的是过渡伪影有上限、可测量、不造成断音。验收按上表测量最大重复/跳过时长，而不是要求零。

跨线程协调：

- 启用/禁用是带代次的宿主状态机：采集侧推进预热并切换写环来源，渲染侧在同一代次提交后切换路径限幅；两侧都在块边界行动，任何一侧都不能提前或部分提交。
- 启用顺序：渲染侧先影子预热路径限幅，预热完成后交叉淡化切入限幅输出；采集侧收到同一代次的就绪确认后，再提交写环从干声到湿声的切换。旧代次的预热结果不能参与新代次。
- 旧代次的预热结果、旧会话的回调不能切换新会话。
- 人声路径限幅在写环切换到湿声之前，用当前干声影子喂入预热；音效路径限幅在启用过渡期用真实音效样本影子喂入并丢弃输出。两者都填满延迟线、收敛增益状态，切换时再纳入输出，避免 2 ms 静音洞。湿声电平若与干声差异较大，由限幅器在 release 时间内收敛，交叉淡化负责遮蔽。
- 关闭过渡期间如果音效仍在播放，音效路径限幅的退出按淡出处理；不把延迟线内容突然丢弃。

预设切换：

- 湿→湿预设切换只提交新参数快照，不重建算法实例、不清空 FIFO。
- 音高、共振峰与效果混合参数在约 20 ms 内平滑；不保证参数阶跃时完全无瞬态，但不允许爆音或断音。
- 关闭变声只通过 `enabled` 开关或临时旁路，不设「原声预设」，因此不存在「处理预设 ↔ 原声」的拓扑切换。
- 热键上/下一个预设只改变预设参数，不改变 `enabled`；循环顺序为内置处理预设在前、用户预设按名称排序在后。

### 与漂移控制和音效时序的关系

- 人声链位于漂移重采样之后，恒定算法延迟不改变稳态环形水位，漂移控制器继续只服务麦克风与输出设备的时钟差。
- 预热期走 tee，干声持续写环，因此不存在「预热消耗输入导致欠载」的问题；不再需要冻结漂移比率。
- 人声链按算法块突发写环，会让推送前瞬时水位出现锯齿。漂移控制器必须使用低通滤波后的水位，或只在块边界更新比率；不能直接用每次回调的瞬时水位，否则小回调下可能反复打到 ±2% 修正上限。
- 低通时间常数应明显大于算法块长（例如 200 ms）；它只平滑水位估计，不进入音频路径，不增加延迟。
- spike 记录水位轨迹与比率时间序列，断言不会长期贴 clamp 振荡；稳态水位保持在目标带内。
- 人声算法延迟只作用于人声。变声启用时，人声与音效各自经过同参数的路径限幅，各增加约 2 ms；两者在混音中的相对时间差仍等于人声算法延迟，目标不超过 30 ms。不为此改变音效触发与单音效门控语义。

### 独立限幅

- 变声启用时，人声与音效分别使用前视限幅器，默认上限 −3 dBFS，左右声道联动。
- 两路限幅后再相加，末端安全限幅默认 −1 dBFS，只处理合并后的过载。
- 人声与音效的增益在各自限幅之前应用，用户提升音量时由本路限幅保护，不把过载转嫁给另一路。
- 变声启用时，人声限幅之后分出试听 tap，试听听到的是实际送往混音的人声；关闭或旁路时，试听记录会话人声链的湿声，回放侧应用 −3 dBFS 试听限幅。
- 停止确认在变声启用时等待音效限幅与末端安全限幅的尾部；关闭或旁路时只等待末端安全限幅。人声继续转发，不参与音效停止判定。
- 诊断分别记录人声、音效与末端安全限幅的增益缩减，界面可继续只显示末端读数。
- 末端安全限幅仍是共享环节：两路同时接近上限时，它会同时压低两路。路径限幅保证正常使用下单路峰值不影响另一路，但不承诺极端过载下完全物理解耦。

## 4. 参数与效果

### 参数模型

| 参数 | 范围 | 语义 |
|---|---|---|
| `enabled` | 布尔 | 总开关；关闭时零延迟旁路 |
| `active_preset` | 预设 ID | 当前处理预设；缺失时回退到 `builtin:female` 并置 `enabled=false` |
| `pitch_semitones` | −24～+24 | 音高移调 |
| `formant_semitones` | −12～+12 | 共振峰搬移；与音高独立 |
| `gate_enabled` | 布尔 | 噪声门开关；关闭时完全直通 |
| `gate_db` | −60～0 | 噪声门阈值；0 dBFS 是最强门限，不表示关闭 |
| `eq_low_enabled` / `eq_mid_enabled` / `eq_high_enabled` | 布尔 | 三段 EQ 各自开关；关闭时直通 |
| `eq_low_db` / `eq_mid_db` / `eq_high_db` | −12～+12 | 三段增益；0 dB 与关闭是不同状态 |
| `drive_enabled` | 布尔 | 软削波开关 |
| `drive` | 0～1 | 软削波量 |
| `robot_enabled` | 布尔 | 环形调制开关 |
| `robot_hz` | 20～1000 | 环形调制频率 |
| `robot_mix` | 0～1 | 环形调制混合 |

每个效果都有显式布尔开关，不使用数值哨兵表示关闭。这样「EQ 开且 0 dB」与「EQ 关」在持久化和界面中都保持区别。

参数校验在配置写入与 IPC 边界完成。越界值拒绝并给出明确错误；配置加载时遇到越界值，按边界钳制并记录警告，不阻断启动。

### 内置预设

内置预设由代码定义，不写入配置文件。实现固定值如下；未列出的 EQ 段关闭且为 0 dB，未列出的效果使用默认值。人工听感校准仍属真机验收，未完成前不写成听感已通过：

| 预设 | 音高 | 共振峰 | 其它 |
|---|---|---|---|
| `builtin:female` | +4 | +3 | 噪声门 −45 dB；高频 EQ +2 dB |
| `builtin:male` | −4 | −3 | 噪声门 −45 dB；低频 EQ +2 dB |
| `builtin:child` | +7 | +5 | 噪声门 −45 dB；高频 EQ +3 dB |
| `builtin:deep` | −6 | −4 | 噪声门 −45 dB；低频 EQ +3 dB |
| `builtin:robot` | 0 | 0 | 噪声门关闭；软削波 0.20；环形调制 50 Hz / 0.80 |
| `builtin:radio` | 0 | 0 | 噪声门 −50 dB；低 −9 / 中 +4 / 高 −9 dB；软削波 0.35 |

机器人与对讲机的音高、共振峰为 0，但仍运行算法实例。这是有意取舍：所有处理预设保持相同的算法延迟，湿→湿切换不产生时间跳变；代价是这两个预设也付出算法 CPU 与约 30 ms 延迟。

### 效果链顺序

```
噪声门 → 音高/共振峰 → 三段 EQ → 软削波 → 环形调制
```

- 噪声门在移调前抑制底噪，避免算法放大静音段；门限使用迟滞与平滑增益，避免硬门沿被频域算法涂抹成预回声。
- 噪声门位置结论：完整链路验证用确定性元音与底噪比较了前置与后置。前置预回声 0.0016、周期性 0.5072；后置 0.0000、0.5067。两种顺序的预回声都低于稳态 1%，没有证据表明前置明显劣于后置，因此保留前置顺序，不调整实现。该结论是离线客观指标，不含人工听感。
- 软削波在人声限幅之前，只负责人声色；人声路径随后经过独立前视限幅，混音后仍经过末端安全限幅。
- 环形调制只用于机器人/对讲机类预设，由 `robot_enabled` 控制；关闭时完全旁路。
- 所有效果器在关闭时直通，不引入额外延迟。

### 效果器固定参数

| 效果 | 固定参数 |
|---|---|
| 噪声门 | attack 5 ms、release 120 ms、hold 50 ms、迟滞 3 dB；阈值由 `gate_db` 提供 |
| 低频 EQ | 低频搁架 200 Hz；增益 `eq_low_db` |
| 中频 EQ | 峰值 1 kHz、Q 0.9；增益 `eq_mid_db` |
| 高频 EQ | 高频搁架 4 kHz；增益 `eq_high_db` |
| 软削波 | 归一化 `tanh`，内部驱动量为 `drive × 10`，输出钳制在 ±1 |
| 环形调制 | 载波 20～1000 Hz，干湿混合由 `robot_mix` 提供 |
| 效果开关 | 20 ms 干湿交叉淡化 |
| 变声启用/关闭 | 25 ms 交叉淡化 |
| 路径限幅切入/退出 | 10 ms 交叉淡化；上限 −3 dBFS，末端安全限幅 −1 dBFS |

### 参数更新

- 参数使用预分配的双缓冲快照：写入方填充非活动槽，再原子切换活动索引；实时线程只加载一次索引并读取该槽，不重试、不等待、不分配。
- 版本变化在块边界应用；同一块内使用同一份参数。
- 预设切换是一次参数快照提交，不逐项生效。
- 参数平滑时间约 20 ms；噪声门与 EQ 的参数可立即生效，但效果开关切换做短时淡化，避免咔哒。

配置写入现有共用 TOML：

```toml
[voice]
enabled = false
active_preset = "builtin:female"
bypass_hotkey = ""
next_preset_hotkey = ""
prev_preset_hotkey = ""

[[voice_presets]]
id = "user:my-voice"
name = "我的女声"
pitch_semitones = 4.0
formant_semitones = 3.0
gate_enabled = true
gate_db = -45.0
eq_low_enabled = false
eq_low_db = 0.0
eq_mid_enabled = false
eq_mid_db = 0.0
eq_high_enabled = false
eq_high_db = 0.0
drive_enabled = false
drive = 0.0
robot_enabled = false
robot_hz = 50.0
robot_mix = 0.8
```

约束：

- 旧配置没有 `[voice]` 时视为关闭，不影响启动。
- 未知键保留往返；注释不承诺持久化。
- 内置预设 ID 以 `builtin:` 开头，用户预设以 `user:` 开头。
- 用户预设创建时由 GUI 生成 ID，格式 `user:<名称派生片段>-<随机短串>`，创建后不变；重命名只改 `name`，不改变 ID；生成时检查重复。
- 顶层与预设条目内的未知键保留往返；条目被删除时其未知键随之移除。
- 激活预设缺失或被删除时回退到 `builtin:female` 并置 `enabled=false`，不静默套用其他预设；加载期与运行期行为一致。
- 重复 ID、空名称、越界参数在加载时拒绝该条并记录警告，其余配置继续可用。
- CLI 的 `config get/set` 支持 `voice.*` 点路径；`config get` 是新增子命令，未知项报错。用户预设通过配置文件或 GUI 管理。
- CLI 同时给出 `--voice-preset` 与 `--voice-off` 时报错，不猜测优先级。

### 配置写入的并发与原子性

这是本特性的前置条件，不是可选优化：

- `Config::save` 改为临时文件写入、刷新并原子重命名；写入失败保留旧文件。
- 进程内只允许一个配置写入点，所有 GUI、热键、遥控的变声状态变更串行提交。
- 高频变更（连续切预设、拖动开关）合并为最后一次落盘，不阻塞音频回调，也不每次整文件写入。
- GUI 的「读—改—写」路径必须保留 `[voice]` 与 `[[voice_presets]]` 的完整内容，不能把未知键或用户预设写丢。
- CLI 与运行中的 GUI 并发写同一配置的风险在文档中明确；至少保证单进程内不交错，跨进程以最后写入为准并保留旧文件可恢复。

### 参数持久化语义

- `enabled` 与 `active_preset` 在变更后串行持久化；连续热键切换合并落盘。
- 选择预设只加载参数，不改变 `enabled`。
- 音高、共振峰与效果参数属于运行期状态。内置预设只读，滑杆修改后必须「另存为用户预设」才能持久化；用户预设修改后必须「保存修改」才能持久化。
- 切换预设时，如果当前有未保存修改，保留一份内存草稿（源预设 ID + 参数），面板显示「恢复未保存修改」。新修改替换旧草稿；应用退出后草稿丢失。
- 未保存的修改与草稿在音频会话重启（释放设备、恢复、重新打开流）后继续沿用；待机→开启音效不重开流，不算会话重启。
- 临时旁路是运行期状态：显式关闭再开启变声、或音频会话重启后清除，按 `enabled` 启动。
- 保存失败时运行期参数已经生效，但界面明确显示「未保存」，不显示「已保存」。

## 6. 控制入口

### 启用与旁路语义

- `enabled` 是持久配置。GUI 启用开关与手机遥控的启用/关闭会更新它，并写回配置。
- 全局旁路热键是临时旁路，只改变运行状态，不写配置；界面显示「临时旁路」。
- 会话重启、显式关闭再开启变声后清除临时旁路，按 `enabled` 启动。
- 选择或切换预设只加载参数，不改变 `enabled`，也不清除临时旁路：
  - 变声已启用时，新预设在块边界生效。

## 7. 人声试听

### 流程

1. 用户点按「试听人声」。
2. 变声已启用：从正式人声限幅之后、与音效混合之前分出一路 tap，写入预分配的 3 秒记录区。试听反映实际送往混音的人声，不包含音效与末端安全限幅。
3. 变声关闭或临时旁路：复用会话人声链，采集回调把麦克风样本喂给它，湿声只写记录区；环形缓冲继续写干声，正式转发保持原声。试听代次变化时复位该链并重新预热。
4. 记录期间显示进度；再次点按取消并清空记录区。
5. 3 秒后停止记录，通过本机输出设备回放。
6. 回放只走本机输出，不送虚拟麦克风，正式转发不中断。

### 状态与边界

- 可用条件是音频会话存活（运行或待机），与 `enabled`、临时旁路无关；未启动或已彻底释放时按钮禁用并显示「音频未启动」。
- 关闭/旁路下的试听复用会话人声链但只写记录区，不改变 `enabled`，不把湿声写入环形缓冲，也不影响对方听到的原声。
- 人声试听与音效试听共用「同一时间只允许一个本机试听」的规则；开始新的试听会取消旧的。
- 人声试听不替换正式播放，也不走音效试听的 `stop_all` 路径；它只借用本机试听的输出仲裁。
- 变声启用时，音效试听复用与正式输出相同的音效路径限幅参数；试听听到的峰值行为与对方听到的一致。试听回放侧的限幅与输出延迟只影响本机试听，不计入正式链路。
- 试听不创建独立算法实例，只通过代次把开始与取消发布给采集/渲染回调；回调不创建、不销毁链，取消或结束后停止写入并复位会话链。
- 准备期间显示「准备试听…」，不写记录区；准备失败显示错误，不开始录制。
- 录制区容量固定，按输出采样率分配；无动态增长。写入只推进原子索引，不加锁；回放前由 Host 冻结记录区并读取，回放期间不再写入。
- 回放设备与录制采样率不同时，复用现有试听路径的重采样规则。
- 录制中发生以下任一情况时取消录制并清空记录区，不播放半段：再次点按、按旁路热键、切换预设、开启或关闭变声、关闭或释放会话、全局停止、开始音效试听。
- 全局「停止播放 / 试听」（空格、托盘、手机停止）同时停止人声试听的录制与回放，与底部按钮文案一致。
- 录制或回放失败显示明确错误；不伪造成功，不留下半段录音。
- 试听不改变当前预设、循环、音量或正式播放状态。

## 8. 与现有行为交界

| 功能 | 变声影响 |
|---|---|
| 正式播放 / 切换 | 无；人声链不进入音效路径 |
| 停止确认 | 变声启用时等待音效限幅与末端安全限幅的尾部；关闭/旁路时只等待末端安全限幅；人声继续转发，不参与音效停止判定 |
| 试听（音效） | 无；与人声试听互斥；变声启用时复用音效路径限幅参数 |
| 试听（人声） | 关闭/旁路时复用会话人声链只录不转发，转发保持原声；不替换正式播放；全局停止会取消 |
| 监听 | 无；监听流仍只放音效 |
| 待机（关闭音效） | 变声继续生效，因为人声转发继续；三类变声热键保持注册 |
| 彻底释放 / 退出 | 彻底释放：人声链随会话回收，变声热键保持注册；进程退出：注销全部热键、join 轮询线程并回收人声链与可恢复草稿 |
| 麦克风校准 | 使用独立于用户旁路的内部旁路；校准结束恢复到校准前的 `enabled`、临时旁路与预设，不改写配置 |
| 自检 | 不经过变声；报告中注明不覆盖人声效果 |
| 电平表 | 显示变声、两路限幅、混音与末端安全限幅之后的转发信号 |
| 麦克风音量 | 在人声限幅之前应用；与变声参数独立 |
| 音效总音量 | 在音效限幅之前应用；不作用于人声 |
| 会话恢复 | 沿用当前变声配置、预设、未保存修改与可恢复草稿 |
| 采样率变化 / 设备热插拔 | 由现有会话恢复流程重建音频流；人声链按新采样率重建，预设参数不变；旧代次的湿声与预热结果不得进入新会话 |
| 会话启动失败 | 人声链在所有者线程回收；试听没有独立实例需要清理；界面保持关闭状态并显示失败原因 |
| 旧会话回调 | 不能改变新会话的人声参数 |

### 独立性边界

| 维度 | 结论 |
|---|---|
| 音频处理路径 | 独立。变声只处理真实麦克风；音效解码、正式播放、音效试听、监听都不经过人声链，音效不会被变声染色。 |
| 开关、配置与预设 | 独立。`[voice]`、用户预设和三类热键与音效条目、槽位热键分开；热键冲突不阻断启动，拒绝冲突绑定并明确提示，不静默覆盖。 |
| 播放门控 | 独立。变声不改变单音效、切换淡出、循环、停止、试听与监听互斥等现有语义。 |
| 待机 | 独立。关闭音效进入待机时，麦克风继续转发并继续变声。 |
| 本机试听 | 互斥。人声试听与音效试听同一时间只允许一个；这是两条本机输出之间的仲裁，不影响正式转发。人声试听在关闭/旁路时复用会话人声链但只写记录区，不把湿声送进正式转发。 |
| 输出混音 | 共享。人声与音效在渲染侧相加，共用末端安全限幅和电平表。 |
| 限幅 | 路径独立，末端共享。变声启用时，人声与音效各自前视限幅后再混合；末端安全限幅只在合并过载时同时影响两路。 |
| 延迟 | 部分共享。变声启用时两路各增加约 2 ms 路径限幅延迟；人声算法延迟只作用于人声，相对时间差仍等于人声算法延迟，目标不超过 30 ms。 |
| CPU 与实时线程 | 共享。人声链在采集回调内运行，限幅在渲染回调内运行；任一超时或分配都会造成整条音频链路欠载，因此零分配和 P99 门槛是硬要求。 |

结论：**功能独立，路径限幅独立；末端安全限幅、CPU 与时钟仍共用**。若要求末端限幅和 CPU 也完全物理解耦，需要独立进程或独立输出设备，不属于本次首发范围。

## 9. 双端要求

### macOS

- 使用现有 CoreAudio 路径；人声链不接触平台设备 API。
- 真机验收包含：启用/旁路、预设切换、三类热键、关闭/启用两态的 3 秒试听、BlackHole 等虚拟设备环回。
- 环回同时测量变声开/关两态的 mic→虚拟设备延迟差值，作为 30 ms 预算的最终裁决。
- 现有 App/DMG 签名与权限流程不变；静态 C++ 库不改变 entitlement。

### Windows

- 使用现有 WASAPI 路径；共享模式下的实际延迟单独测量，不用 macOS 数据推算。
- 真机验收包含：启用/旁路、预设切换、三类热键、关闭/启用两态的 3 秒试听、VB-CABLE 环回。
- 环回同时测量变声开/关两态的 mic→虚拟设备延迟差值，不用 macOS 数据推算。
- NSIS 安装包必须包含完整静态链接的算法库，安装后无缺失 DLL。
- Windows 原生 CI 编译含人声链的 workspace；这是权威编译检查。
- 构建机需具备 MSVC C++ 工具链与 libclang（`signalsmith-stretch` 的 `bindgen` 依赖）。CI 与本地 Windows 真机都必须验证从零 `cargo build`，不能只在已有缓存的机器上通过。
- C++ 对象优先使用静态 CRT，或在干净 Windows 机器上验证 `msvcp140.dll` / `vcruntime140.dll` 不缺失；两者选一并写进打包验收。
- 交叉检查路线确定为 feature 隔离：`audio-core` 的 `voice` feature **默认关闭**，C++ 后端只在该 feature 后编译；GUI/CLI 以 `default-features=false` 依赖 `audio-core`，并用各自的默认 `voice` feature 开启它。其他 crate 不开启该 feature。
- 正常构建 GUI/CLI 时默认 feature 打开，变声代码参与编译。提交门禁显式运行 `cargo test -p audio-core --features voice`，不依赖 workspace 的 feature 统一来运行 voice 单元测试。
- `tools/win-cross-check.sh` 以 `--workspace --no-default-features` 运行，关闭 GUI/CLI 的默认 `voice` feature；脚本必须打印「变声代码未参与本次交叉检查，Windows 原生 CI 与真机构建才是权威」。
- Windows 原生 CI 与真机构建使用默认 feature，编译完整 C++ 后端；这是变声代码的权威编译检查。
- 不接受受控 `cl.exe` 桩作为最终方案；桩无法证明 C++ 对象真实可编译，且会掩盖 bindgen 与 CRT 问题。
- 该脚本必须显式打印跳过原因；不能静默失败、不能把缺少 `cl.exe` 误报成代码缺陷。

### 打包与合规

- 新增依赖更新 `Cargo.lock`。
- 用现有脚本重建 `THIRD-PARTY-NOTICES.md`；确认 Signalsmith 的版权与 MIT 文本被收录。
- 产品名称、权限文案、双端构建脚本与名称回归同步检查。
- 两端发布包来自同一提交与锁文件。

## 10. 技术验证

### 隔离方式

验证代码放独立 crate `tools/voice-spike/`，自带 `[workspace]`，不加入根 workspace，避免 C++ 依赖提前打断现有双端门禁。验证结束可删除或保留为历史记录。

Signalsmith 的 Rust 包装在构建期强制使用 `bindgen`，需要 libclang。验证必须分别在 macOS 与 Windows 真机/CI 上确认 `cargo build` 能完成；Windows 缺少 LLVM/libclang 时，记录安装要求，或评估不依赖 bindgen 的 `ssstretch` 包装。

| Signalsmith Stretch | 块长分别试 5 / 10 / 20 / 40 ms，间隔取块长一半 |
| `pitch_shift` | 固定 128 样本块，只音高 |

### 测量项

1. 算法延迟：库报告的输入/输出延迟加 FIFO 与分块开销；用脉冲信号离线对齐验证。
2. CPU：48 kHz 单声道连续处理 60 秒，记录每块耗时 P50 / P99 / 最大值；分别在 128 / 256 / 512 帧回调粒度下测单次最坏耗时，并比较 `splitComputation` 开/关。
3. 实时安全：分配计数 allocator 同时包住 `process()` 与 `set_transpose_factor` / `set_formant_factor`，确认零分配；检查锁与文件 IO。
4. 音质：正弦扫频测音高比；元音样本测共振峰搬移；44.1 kHz 与 48 kHz 下同一预设的共振峰搬移量对比；生成 A/B WAV 供人耳试听。
5. 漂移与块稳定性：模拟不同采集回调大小，记录环形水位轨迹与漂移比率时间序列；确认不丢帧、不累积漂移、不长期贴 ±2% 修正上限。
6. 过渡连续性：用 PCM 断言启用、关闭、湿→湿切预设、湿→关闭/旁路四种过渡的最大重复/跳过时长、静音长度与爆音。
7. 双端一致性：macOS 本地与 Windows CI/真机跑同一份离线基准，分别记录。
8. 构建路线：在 spike 阶段验证 `voice` feature 隔离后的 `--no-default-features` 交叉检查输出，以及 Windows 默认 feature 的完整构建。

### 门槛

Signalsmith：

- 新增算法延迟不超过 30 ms。
- P99 单核占用不超过 15%，且单次回调最坏耗时小于最小支持回调周期。
- `process()` 与参数 setter 在回调路径零分配。
- 10 分钟连续处理无欠载，漂移比率不长期贴 clamp。
- 共振峰听感明显可辨，±3、±7、±12 半音下无明显颤音或金属声；44.1 kHz 与 48 kHz 的搬移量差不超过 1 半音的听感范围。
- 过渡重复/跳过不超过算法延迟 L，无爆音、无欠载、无长断音。

`pitch_shift`：

- 新增延迟不超过 25 ms。
- P99 单核占用不超过 10%。
- 回调路径零分配。
- 作为无共振峰后备方案，不满足完整档的产品要求。

选型规则：首发档位要求共振峰控制，因此 Signalsmith 达标时直接采用。Signalsmith 未达标时，不能用 `pitch_shift` 静默替代完整档；只能由产品明确缩减范围，或暂停集成并评估 WORLD、Rubber Band 商业授权等替代方案。

两者都不达标时暂停生产集成，重新评估 WORLD 或购买 Rubber Band 商业授权；不通过牺牲验收门槛强行交付。

| 会话 / Host | 待机仍变声且变声热键保持注册；恢复沿用设置；运行期参数更新；预设切换不重置实例；草稿可恢复；停止尾部按当前限幅链计算；旧回复不覆盖新状态 |
| 试听 | 启用态 tap 在人声限幅之后；关闭/旁路态复用会话人声链只录不转发；3 秒录制、取消、回放、与音效试听互斥；全局停止会取消；失败提示 |
| GUI | 交付 DOM→IPC 回归；滑杆、效果开关、预设保存/删除、保存失败、草稿恢复、外部切预设刷新、焦点与代次；热键配置入口 |
| 热键 | 三类绑定注册；冲突不阻断启动并明确提示；重绑失败保留旧键；待机保持注册；无会话切预设更新待用参数、按旁路只提示；旧会话事件不影响新会话 |
| 遥控 | 启用开关与预设切换请求顺序；用户预设渲染与转义；临时旁路只读显示；退休会话、端口回收 |
| 平台 | macOS 真机环回；变声开/关延迟差值；Windows 交叉检查显式跳过说明；Windows 原生 CI；Windows 真机环回与延迟差值 |
| 交付 | 打包名称、静态/动态 CRT 与 DLL、许可证声明、README 与项目上下文更新 |

## 13. 风险与回滚

| 风险 | 应对 |
|---|---|
| 小块下音质下降 | 技术验证记录块长拐点；不硬压延迟牺牲可懂度 |
| 启用/关闭的时间不连续被用户听成重复或跳字 | 验收量化重复/跳过上限；交叉淡化只避免爆音与突变，不消除重复/跳过；文案不承诺零空隙。若听感不可接受，再评估对齐延迟线方案 |
| C++ 构建打断 Windows 门禁 | spike 隔离；`voice` feature 让交叉检查显式跳过；Windows 原生 CI 为权威 |
| Windows 缺少 libclang 导致 bindgen 失败 | 技术验证先做从零构建；CI 与真机安装 LLVM；必要时改用 `ssstretch` 或预生成绑定 |
| Windows 实际延迟高于 macOS | 双端分别测量；Windows 真机未通过不发布 |
| CPU 峰值导致爆音 | 记录 P99、最大值与单次回调最坏耗时；预分配；必要时减小块长或降低效果数量；Rust 包装未暴露 `splitComputation`，不在首发假设中 |
| 漂移控制器追块量化噪声 | 水位低通或块边界更新；spike 记录水位与比率；不长期贴 clamp |
| 配置写入损坏或相互覆盖 | 原子写入、单进程写入点、高频变更合并；写入中 kill 的恢复回归 |
| 待机时变声热键被注销 | 拆分音效槽位与变声动作的热键生命周期；待机保持变声热键注册 |
| 试听与音效试听重叠 | 本机试听统一互斥；开始新的取消旧的；全局停止取消人声试听 |
| 试听复用会话链带来状态耦合 | 只在试听代次内写记录区；取消/完成/阶段变化立即复位链；不新建算法实例，不写正式转发 |
| 独立限幅的残余耦合 | 路径限幅保护单路；末端安全限幅只在合并过载时同时影响两路。验收明确区分正常范围与极端过载 |
| 路径限幅增加延迟与响度变化 | 两路各约 2 ms；上限默认 −3 dBFS，按技术验证与真机听感校准，不牺牲末端过载保护 |
| 产品预期过高 | 文案写清经典 DSP 能力边界；不承诺音色克隆 |
| 用户预设损坏 | 单条拒绝并记录警告；其余配置继续可用 |
| 变声影响现有链路 | 默认关闭；关闭或临时旁路时保持现有单限幅链；启用时音效仅增加独立路径限幅，音效素材本身不被处理；试听、监听、自检不经过人声链 |
| Windows CRT 动态依赖 | 优先静态 CRT，或在干净机器验证 DLL 不缺失 |

回滚路径：

- 关闭 `voice.enabled` 即回到原声直通。
- 删除或禁用用户预设不影响启动。
- 算法后端可按 crate 特性或构建配置移除；移除后变声功能不可用并保持原声直通，音效、试听、监听功能不变。
- Windows 或 macOS 任一端未通过真机验收时，不发布该端安装包。

## 14. 假设与待验证

- 10 ms 算法块长能否同时满足延迟与音质门槛；单次回调最坏耗时能否压进 128 帧周期（Rust 包装没有 `splitComputation` 可分摊负载）。
- Signalsmith 的共振峰控制在目标预设下的可辨度，以及 44.1 kHz 与 48 kHz 的一致性。
- 噪声门放在移调前还是移调后，哪种涂抹更少。
- Windows WASAPI 共享模式下的实际新增延迟。
- 低配 Windows 机器上的 CPU 余量。
- 3 秒试听长度是否足够用户判断效果；试听复用链重新预热的时长是否可接受。
- 启用/关闭时最多 L ms 的重复或跳过，用户是否能接受；交叉淡化时长是否足够遮蔽。
- −3 dBFS 路径限幅与 −1 dBFS 末端安全限幅在目标设备上的实际响度、独立性与过载保护表现。

macOS 本地与双端 CI 的 30 秒矩阵、600 秒离线浸泡已取得；指标先行选型为 Signalsmith Stretch 10 ms 块。
完整链路已在进程内验证：44.1 kHz 与 48 kHz 的移调比差 0.338 半音、共振峰质心差 0.564 半音，均在 1 半音门槛内；这些是离线客观指标，44.1 kHz 真机、人工听感与 Windows 真机仍是生产验收门槛。

这些假设由技术验证与真机验收回答，不在实现前用估计值替代。
