# 播放操作组合回归

日期：2026-10-12。范围：桌面 GUI、宿主路由、共用播放器、主输出、监听及独立试听。
macOS 和 Windows 使用相同实现及相同回归；平台原生驱动实测另列。

## 行为约定

| 操作组合 | 预期行为 |
|---|---|
| 播放 A → 播放 B | A 淡出后 B 开始，每个输出帧只有一条音效，最终高亮 B。 |
| 播放 A → 再次播放 A | 从头重播 A；只有一个活动音效。 |
| 播放 A → 试听 B | 主输出、监听的 A 停止确认后，B 仅在试听输出发声。 |
| 试听 A → 播放 B | 旧试听流关闭后才发布 B 的主输出、监听样本。 |
| 试听 A → 试听 B | 旧试听被替换，解码完成迟到也不能恢复 A。 |
| 播放 / 试听 → 停止播放 | 取消活动音效、待切换音效及旧后台请求，麦克风继续转发。 |
| 停止 → 新播放 / 试听 | 新的合法操作可以正常执行；旧停止回复不能停止新选择或覆盖新反馈。 |
| 开启循环 → 播放 / 切换 | 重复当前一条音效，切换仍保持单音效。 |
| 播放中关闭循环 | 游标不重置，本轮结束后停止，后续触发只播放一次。 |
| 循环任意状态 → 试听 | 试听始终只播放一次。 |
| 启动期间改变循环 | 设置落到新会话，不重新开流或重播音效。 |
| 关闭音效 → 试听 / 修改循环 → 开启音效 | 待机保留麦克风会话；试听仅自己听；恢复使用最新设置。 |
| 无效槽位 / 排满队列 → 拒绝播放 | 保留原音效及合法试听，包括仍在解码的试听。 |
| 旧会话回调 → 新会话 | 已退休的热键、手机回调不能修改新会话或使新票据失效。 |
| 跳过坏音频 → 点击有效卡片 | 卡片、稳定文件 ID、加载槽位、时长和热键一致。 |

## 本轮复现并修复的问题

### 1. 停止完成后，旧后台任务重新出声

最小序列：旧播放 / 试听已经提交到后台，但尚未进入 Host；新停止先完成；释放旧 worker。
修复前，主输出、监听或试听重新输出非零 PCM。两项 Host 复现最初均失败。

处理：GUI 在重操作之前领取 Host 操作票据；后台在接纳时拒绝过期请求。
关闭旧试听流可能耗时，播放器的可取消屏障在关闭完成后再次复核，过期请求不会发布 Play。
热键、手机和托盘参与同一序列，预定票据的短状态锁不覆盖解码、开流、关流或等待。

### 2. 启动期间取消循环未落到新会话

最小序列：开始启动时循环为 `true`，native 启动尚未完成，用户取消循环。
修复前只保存了偏好，新会话仍用 `true`。真实 DOM→IPC 回归已先失败再通过。

处理：启动使用明确配置快照；启动成功后将期间的新选择更新到新会话。
循环更新仍独立于播放命令，不重置进度，布尔 `false` 明确保留。

### 3. 旧回复、旧状态和旧提示覆盖最新操作

复现包括播放 / 试听回复晚于停止、旧失败回复晚于新播放、循环回复晚于停止、外部入口取消 GUI 请求。
处理：播放系列共享界面操作代次；旧回复不发起新状态刷新、不覆盖提示。
native 返回操作是否仍有效，取消结果只跟随真实状态刷新。
关闭 / 释放后立即清理本次操作的缓存，再使用新状态；不在新状态返回后强行覆盖新控制入口的选择。

### 4. 启动跳过坏文件后，卡片仍绑定旧槽位

最小序列：界面原有 A、B；A 解码失败，实际只加载 B 为槽位 0；启动后仍保留两张旧卡片。
修复前可点击错误槽位或把 B 的状态画到 A 卡片。DOM 回归捕获 `2 !== 1`。
处理：最新启动状态返回后，按实际加载的稳定 ID 和槽位重建卡片及事件绑定。

### 5. 手机页面播放与停止请求可乱序执行

原页面直接并发 `fetch`；慢播放与后续停止可能按相反次序在服务端执行。
修复：同一页面按点击顺序发送请求，较新操作的反馈覆盖较旧操作；失败不阻断后续请求。
测试直接执行 Rust 页面实际嵌入的脚本，4 项检查先全部失败、修复后全部通过。
另通过真实 localhost HTTP 路由驱动实际 PCM 验证切换、停止、拒绝、循环和重播。

| 层次 | 检查内容 | 证据 |

## 证据边界

音频证据来自真实 `RenderProcessor` 及 Host 路由的进程内 PCM，后端设备为可控替身；
没有打开用户的麦克风或音箱，没有修改用户配置，也没有退出正在运行的 App。
GUI 测试使用实际交付 HTML / JavaScript，IPC 为替身。
浏览器曾通过 21 个真实交互，随后从截图发现启动卡片缺陷；最终卡片和取消边界由交付 DOM 回归验证，
不把早先浏览器验收当成最终代码的全部验收。
Windows 交叉检查只验证所有代码和测试目标可编译，不链接安装包，也不证明 WASAPI 真机出声。
