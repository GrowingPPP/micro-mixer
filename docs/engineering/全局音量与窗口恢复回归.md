# 全局音量与窗口恢复回归

日期：2026-10-12。适用范围：桌面 GUI、共用 Host 与 macOS / Windows 窗口恢复策略。

## 行为约定

| 控件 / 操作 | 预期行为 |
|---|---|
| 麦克风音量 | 调整正式输出中的人声；不调整音效、监听或试听 |
| 音效总音量 | 与卡片音效增益叠加，共用于试听、正式播放和监听 |
| 未启动 / 待机时调节音量 | 保留并保存设置；下次试听立即使用当前总音量 |
| 正在解码 / 开流时调节音量 | 首次出声及会话发布使用最新设置，旧配置不能覆盖 |
| 播放中调节音量 | 更新实际 PCM，不重播、不重开流 |
| 输完音量立即试听或正式播放 | 先提交尚未到期的输入，再触发播放 |
| 等待音量请求时停止 | 停止可立即派发，迟到的播放 / 试听不再执行 |
| 关闭主窗口 | 仅隐藏；现有音频会话继续按原状态运行 |
| macOS 点击 Dock | 显示、取消最小化并聚焦现有主窗口 |
| 双端托盘恢复 | 使用与 Dock 相同的窗口恢复策略，不重建窗口或音频会话 |

全局 GUI 控件范围为 −60～+36 dB，−60 dB 静音；卡片范围为 −40～+12 dB。
旧配置恢复时按对应控件范围限制，显示值、IPC 与保存值保持一致。原生 Host 对总音量、卡片音量和
启动参数中的素材增益统一拒绝非有限值及超过 +36 dB 的值；更小的负值保留静音语义。

## 确认的问题与实现

### 试听没有使用总音量

此前试听回调仅使用卡片增益，Host 在没有会话时也不保存全局音量；前端未启动时直接跳过音量 IPC。
新增默认总音量、实时更新、解码中更新及高增益 PCM 回归先失败，证实问题存在。

现在 Host 在会话之外保存音量，试听读取共享的总增益原子并叠加卡片增益；
前端恢复配置、未启动修改、立即播放及慢启动完成时同步当前设置。音量 IPC 与配置保存各自串行，
播放代次在等待前后复核，避免停止后的迟到请求再次触发播放。

试听复用 `audio-core::Limiter`，采用与正式输出相同的立体声联动限幅及设备声道映射。
所有者线程等前视尾部排完后关流；回调只处理预分配状态，不分配或阻塞等待。

独立复核发现极大但有限的两个增益相乘仍可能溢出，补上 +36 dB 上限和旧卡片配置处理。
相关回归断言被拒绝的输入不改变有效设置，PCM 不含 NaN 或无穷值。

### macOS 关闭后点击 Dock 无法恢复

此前主窗口关闭请求被拦截并隐藏，但 Tauri 应用循环没有处理 macOS `RunEvent::Reopen`。
现在 Dock 事件与托盘恢复共用 `window_lifecycle` 策略，恢复已有 `main` 窗口；
显示、取消最小化及聚焦分别尝试，单个动作失败不阻断其他动作。

## 回归入口

```sh
cargo test --locked -p mixer-gui --bin mixer-gui host::tests -- --nocapture
cargo test --locked -p mixer-gui --bin mixer-gui window_lifecycle::tests -- --nocapture
node --test tools/test-gui-controls.js
```

- Host 实际 PCM 覆盖默认总增益、卡片叠加、实时调整、解码 / 开流期间修改、过期与无效输入，
  并比较试听、正式播放和监听的增益及限幅上限，覆盖单声道、双声道和多声道映射。
- 短音频回归先确认所有者已经观察到源样本耗尽且仍持有流，再排空前视尾部，
  确认自动关闭、PCM 回收和保留的旧回调静音。删除排尾等待条件时回归必须失败。
- 交付 DOM→IPC 覆盖名称与用途、零值恢复、未启动保存、输入范围、立即试听 / 播放、
  慢请求顺序、停止取消及启动期间更新。
- 窗口策略覆盖隐藏后恢复、隐藏且最小化、已显示时聚焦、单个恢复动作失败及窗口不存在。

## 验证边界

音量一致指同一素材和设置采用相同的软件增益、限幅参数及声道处理规则。
不同物理设备的系统音量、不同采样率及正式输出混入人声引起的限幅，可能影响实际听感。
受控 PCM 不替代真实声卡环回；窗口策略回归不替代原生 Dock 事件验收。
双端共用前端与 Host，Windows 交叉类型检查不代表 Windows 真机或安装包已经通过。

2026-10-12 用户在 macOS 自行测试后确认「dock 点击可以弹窗了」，Dock 恢复按用户真机反馈验收通过。
自动化工具的 Dock 读取曾超时，因此该原生结果注明来自用户反馈。
