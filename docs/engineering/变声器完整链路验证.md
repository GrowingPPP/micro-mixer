# 变声器完整链路验证

本文记录变声功能从采集、参数快照、效果链、路径限幅、混音、试听、停止到待机/重建/释放的完整链路回归与离线性能证据。

## 证据等级与边界

- **等级 B：进程内 PCM 与可控后端。** 所有数据来自离线连续处理、`DelayBackend` / `GainBackend` / `FakeBackend`、固定 PCM 夹具和本机回环 socket，不依赖真实声卡、系统默认设备或用户音频目录。
- 性能数据是进程内墙钟与分配计数，**不是真实音频回调**，不能替代 macOS/Windows 真机回调验收。
- 44.1 kHz / 48 kHz、待机、重建、释放和热键生命周期均由可控后端验证；没有执行真机环回、人工听感、Windows 原生 CI、安装包或 DLL 验收。
- 本机环境：macOS 26.6.1（Apple M1 Pro，8 核），rustc/cargo 1.99.0，Node.js v22.19.0；workspace `dev` 配置为 `opt-level = 1`，依赖为 `opt-level = 2`。
- 未执行项：真实设备延迟、真实回调 P99、Windows 真机/安装包、人工听感、44.1 kHz 真机环回。

| 最大回调耗时 | 140–188 µs |
| 分配计数 | 0 |
| 欠载 / 溢出 | 0 / 0 |
| 漂移比率范围 | 0.980000 .. 1.000023 |
| 漂移贴 ±2% 上限 | 250 / 59800 步（0.42%，启动收敛段） |

说明：主表是 `DelayBackend` 的进程内数据，**不含移调/共振峰 DSP**；真实 Signalsmith 数据见 `变声器技术验证.md` 与下方专项预算。浸泡中的 P99 按 10 ms 周期的 15% 断言；最大墙钟值只记录，因为并行测试进程包含调度抢占。单次回调最坏耗时由两个单线程预算回归分别断言（DelayBackend 128 / 256 / 480 帧；Signalsmith 128 / 480 帧，最大值均小于各自周期）。上述数据不替代真实回调。

### 含移调/共振峰 DSP 的实时预算

`含移调后端的回调预算` 使用 Signalsmith +4 半音 / 共振峰 +3 半音与完整效果链，单线程、每种回调 5 秒音频：

| 回调帧 | 周期 | P99 | 最大 |
|---|---|---|---|
| 128 | 2.667 ms | 54 µs | 80–94 µs |
| 480 | 10.000 ms | 84 µs | 87–122 µs |

两种回调的 P99 都低于周期 15%，最大值都小于周期；Rust 侧分配与欠载为 0。C++ 内部堆分配不计入 Rust 分配计数，与 `变声器技术验证.md` 的口径一致。该数据是离线进程内测量，不是真实设备回调。

## 44.1 kHz / 48 kHz 一致性

同一预设（噪声门 −60 dB、三段 EQ、软削波、50 Hz 环形调制 0.5）在两种采样率下：

| 指标 | 44.1 kHz | 48 kHz |
|---|---|---|
| 稳态 RMS | 0.2964249 | 0.29640335 |
| 170 / 220 / 270 / 440 / 660 Hz 分量 | 0.170975 / 0.341951 / 0.170974 / ~0 / 0.015031 | 0.170965 / 0.341926 / 0.170965 / ~0 / 0.015028 |
| 移调比（+7 半音，220 Hz 输入） | 1.484458 | 1.4557486 |
| 相对标称 1.498307 的偏差 | 0.161 半音 | 0.499 半音 |
| 两种采样率移调差 | — | 0.338 半音（门槛 ≤ 1 半音） |
| 共振峰 +7 半音质心比（元音谱谐波包络） | 1.1999 | 1.1614 |
| 两种采样率共振峰差 | — | 0.564 半音（门槛 ≤ 1 半音） |

效果链绝对锚点（两种采样率都必须满足）：稳态 RMS > 0.25；170 / 270 Hz 边带 > 0.1；220 Hz 载波 0.34 ± 5%；660 Hz 驱动谐波 > 0.005。共振峰质心比必须 > 1.05，以排除 formant 参数被忽略时两端同为 1.0 的变异；该质心比不是名义半音倍数。

两种采样率的会话输出、路径限幅 −3 dBFS、末端限幅 −1 dBFS 与三秒试听容量一致。移调比采用自相关基频估计；10 ms 块长下的频域算法存在少量频率涂抹，该数据不是人工听感。

## 噪声门前置 / 后置对比

确定性元音（220 Hz 谐波，前 400 ms 为 −50 dBFS 底噪）经 Signalsmith +7 半音处理，同一噪声门分别位于移调前与移调后：

| 顺序 | 预回声 / 稳态 | 周期性（可懂度代理） |
|---|---|---|
| 前置（当前设计） | 0.0016 | 0.5072 |
| 后置 | 0.0000 | 0.5067 |

两种顺序的预回声都低于稳态 1%，前置没有出现明显劣于后置的证据，周期性相同。因此保留「噪声门 → 音高/共振峰 → EQ → 软削波 → 环形调制」的设计顺序，不修改实现与设计文档。该结论是离线客观指标，不包含人工听感。

## 本轮修复

**待机时手机「全部停止」无法取消本机试听。**

- 现象：进入待机后播放路由被清空，遥控 `/stop` 在检查播放控制前直接返回「音频未启动」；停止处理器也被一并清除。正在录制的人声试听继续运行；待机时启动的音效试听同样不会被手机停止。
- 修复：待机改用 `Shared::clear_playback`，只清播放控制、槽位、播放处理器与回传钩子，保留停止处理器和变声路由；遥控 `/stop` 在播放控制判空之前处理，`stop_all` 返回是否真的接住请求。
- 停止处理器改为按会话代次预约停止票据，只清除属于该会话的试听控制，不要求 `playback.active()`；只有播放活跃时才向引擎提交 `stop_all`。因此待机停止能静音人声与音效试听，又不会重新发布播放控制或启动音效。
- 回归：`待机时停止请求不依赖播放控制即可到达宿主`（遥控 HTTP）、`待机时手机停止取消人声试听且不启动播放`（宿主，实际 PCM/线程断言）、`待机时手机停止取消音效试听`（待机音效试听 PCM 静音）。
- 遥控 HTTP 测试的本地读取等待上调到 5 s，仅吸收 workspace 并行负载下的调度抖动，不放宽路由或内容断言。

## 残余风险

- 真实设备回调、CoreAudio/WASAPI 延迟与欠载行为未在本轮验证。
- Windows 原生 CI、NSIS 安装包、DLL 检查与真机安装未在本轮执行。
- 44.1 kHz 真机环回与人工听感未执行；移调比数据来自离线自相关估计。
- 进程内 P99/最大值包含测试测量开销，不能直接换算为产品占用率；主浸泡表使用 DelayBackend，不含移调/共振峰 DSP，Signalsmith 专项预算单独列出。
- 遥控 HTTP 回归使用本机回环与 5 s 等待；并行负载下的调度抖动不再被误报为路由失败。
