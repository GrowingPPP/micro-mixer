# 打包名称与兼容性

当前公开名称为 **麦克风混音助手**。界面、系统权限提示、安装引导及分发产物使用这一名称。

## 名称来源与产物

`apps/mixer-gui/tauri.conf.json` 的 `productName` 是打包名称来源：

- macOS 打包脚本和 `m0/tools/app_verify.sh` 通过共用的 `tools/app-product-name.sh` 读取它。
- App、DMG 文件名、DMG 卷名、首次打开说明及挂载后的 App 校验路径使用同一个名称。
- Windows 打包脚本直接读取该配置，只接受当前产品名和版本对应的 NSIS 安装包；其他名称或版本的旧包不会被当成本次产物。
- 名称允许中文与空格。两端拒绝空名称和不能用作跨平台文件名的字符。

可以先查看 macOS 产物路径，命令不会构建、签名、挂载磁盘或操作音频设备：

```sh
./apps/mixer-gui/build-app.sh --print-artifact-paths
./apps/mixer-gui/build-app.sh --print-first-open-note
./m0/tools/app_verify.sh --print-app-path
```

公开名称调整后，应用 identifier 仍为 `dev.local.mixer`，可执行文件仍为 `mixer-gui`，用户配置目录沿用原路径。目录和文件选择不受产品名称影响。

## 第三方声明与变声依赖

变声默认编入 GUI 和 CLI，使用 `signalsmith-stretch`（MIT，捆绑上游 C++ 实现）以及构建期的 `cc`、`bindgen`、`clang-sys`。依赖变化后重新生成声明：

```sh
python3 tools/gen-third-party-notices.py
```

当前声明包含 `signalsmith-stretch 0.1.3` 的 crate 根许可证（`Copyright 2024 Colin Marc`），以及随 crate 打包的 vendored 子模块许可证：

- `signalsmith-stretch/signalsmith-stretch.h`（`Copyright (c) 2022 Geraint Luff / Signalsmith Audio Ltd.`）
- `signalsmith-linear/stft.h`（`Copyright (c) 2025 Signalsmith Audio`）

这两个头文件由 `cc` 静态编入可执行文件，其版权声明必须随二进制保留。生成脚本会读取 crate 根目录及每个一级子目录中的许可证文件，并排除 `copying.rs` 这类源码文件。声明同时包含 `cc`、`bindgen` 与 `clang-sys` 的清单条目；许可证原文取自本地 cargo registry 中各 crate 随包分发的文件。

macOS 打包脚本在签名前把 `LICENSE`、`THIRD-PARTY-NOTICES.md` 放入 App 的 `Contents/Resources/`，DMG 盘面另放 `LICENSE` 与 `第三方依赖声明.md`。挂载 DMG 后的校验会检查 App 包内两份文件与盘面声明，缺失时构建失败。Windows 的 NSIS 安装目录靠 `tauri.conf.json` 的 `bundle.resources` 收录这两份文件：映射写法把 `../../LICENSE` 与 `../../THIRD-PARTY-NOTICES.md` 装到安装根目录，源路径相对配置文件所在目录解析，macOS App 包的落点与之相同。`build-app-windows.ps1` 在构建前核对声明与源文件，构建后在 Tauri 生成的 `target\release\nsis\<架构>\installer.nsi` 里核对两份文件被收录，缺失则失败；找不到该脚本时只给出警告，改由真机安装后核对。脚本另把两份文件复制到安装包输出目录（`-NoInstaller` 时复制到 `target\release`），缺少任一源文件时构建失败，该副本只是便于不安装就能查看，不是安装内容的依据。

变声算法的 C++ 代码由 `cc` 静态编入可执行文件，没有单独的算法 DLL。但构建没有设置静态 CRT（`crt-static`），`msvcp140.dll` / `vcruntime140.dll` 仍可能是动态依赖；安装包安装后目录是否含这两份声明、干净机器上是否缺少上述 CRT DLL，都由 Windows 真机安装验收确认，当前不写成已通过。

## 回归与验证边界

```sh
node --test tools/test-app-packaging.js
```

这组回归实际运行交付的 macOS 脚本，覆盖当前名、中文带空格名、英文带空格名和无效名称，并真正渲染 DMG 内的首次打开说明，防止中文标点紧邻变量时被 Bash 当作变量名的一部分；同时检查两端名称使用、macOS 四项系统用途说明，第三方声明包含 `signalsmith-stretch`、`cc`、`bindgen`、`clang-sys` 并随双端产物复制和校验，以及 `bundle.resources` 把许可证与第三方声明装进安装根目录、macOS 落点一致、构建脚本接线。它不需要真实声卡，不关闭正在运行的 App，也不修改用户配置。

Windows 原生脚本回归通过以下命令运行，包含名称解析、中文空格名、旧名称/旧版本包筛选、分发文件复制、安装资源声明与 NSIS 脚本收录核对和原有冒烟门禁：

```powershell
.\apps\mixer-gui\build-app-windows.ps1 -TestSmokeHarness
```

两项均接入质量 CI；macOS 检查接入 `tools/check-all.sh`。Windows CI 执行 PowerShell 原生回归，不能用 macOS 上的源码检查代替其执行结果。真实 NSIS 安装和 macOS App/DMG 签名仍由对应平台的打包脚本校验。

历史调研中的产品类别名称及旧版本变更记录保留原文；当前使用指令与打包路径采用新名称。

## 软件简介与目录支持

顶栏「关于」展示软件简介、正式播放和本机试听的区别、连接方法及版本信息。
名称、版本通过共用的 `app_info` 命令读取打包配置；打开或关闭窗口不会改变音频会话。
对 Windows 的 VB-CABLE，说明明确区分软件输出 `CABLE Input` 与目标应用麦克风 `CABLE Output`。
当前面向用户的桌面、CLI 和手机遥控文案使用「对方」。

音频来源不限于 `~/Downloads`。原生选择器接受任意有读取权限的文件夹或音频文件；
目录扫描只扫描当前层。载入文件夹替换列表，「添加文件」可以从不同目录追加。
macOS 下载、桌面、文稿受系统隐私权限保护，首次访问需要允许读取；外部存储需要保持挂载且可读。

配置保存、恢复的 `~/` 展开与 GUI 使用同一主目录规则：macOS 使用 `HOME`，Windows 使用 `USERPROFILE`。
绝对路径和 UNC 路径保持不变，测试通过平台和环境注入验证，不修改全局环境变量。
